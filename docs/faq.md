# 常见问题

## 端口

### 启动时提示端口被占用怎么办？

中枢会在 8788–8799 内自动顺延。需要固定中枢端口时使用 `--port <n>`，并确保防火墙允许。

项目使用的面板、应用与数据库端口由中枢在加入项目时一次性预约，写入该项目的 `config/panel.json`。不要手工修改其中的端口——数据库连接串、`.env` 中的 `DATABASE_URL` 与 `AGILECAMPUS_URL` 都由端口派生，单独改一个会静默失同步。

需要更换端口时，在中枢中点击「重新分配端口」。它会停止正在运行的应用与数据库，同时更新三个端口及全部派生配置，再按原状态拉起。

## 仓库与数据

### 面板会修改我的源码仓库吗？

不会。ac-launcher 对源仓库只读，所有构建产物、数据库、日志与配置都写在运行目录中。可以用以下命令取证：

```bash
node verify-repo.mjs --repo <仓库> save manifest.json
node verify-repo.mjs --repo <仓库> diff manifest.json
```

### 更新源码后数据库报「列不存在 / 表不存在」，又不想丢数据怎么办？

点击操作栏的「修复表结构（保留数据）」。它只把运行目录里那份源码的 `src/db/schema.ts` 推到数据库，不做构建，也不清空数据。

遇到 `DROP TABLE` / `TRUNCATE` 这类会丢数据的变更时，它会先停下来，把变更计划打在任务日志里；确认无误后再点一次「确认执行」才会真正执行。

如果仓库刚拉过新提交，先点「仅同步源码」，再修复表结构。

### 列表里出现多条「收编的旧部署」怎么办？

升级到包含本次修复的版本后，重新启动一次中枢即可。启动时会按规范化后的运行目录与仓库路径合并重复条目，并把结果写回 `projects.json`；旧版本按字符串比较路径，同一目录的另一种写法（大小写、junction、8.3 短名）可能被当成另一套部署，于是每换一种写法启动就多收编一条。

合并只删除注册表里的重复**条目**，磁盘上的部署文件一个都不会动。确实不再需要的那一套，用「删除并清盘」清理。

### 如何手动清理旧 engine / 部署？

运行目录下的 `engine/<hash>/` 是便携版 exe 释放的引擎源码副本，可按需清理；正在被进程使用的副本不会被 `verify-engine.mjs` 允许删除。

删除整个项目请在中枢中使用「删除并清盘」，不要手工删目录：收编的旧部署运行目录就是数据根，手工清理容易连同中枢的注册表一起删掉。相关边界由 `verify-legacypurge.mjs` 守护。

## 部署与构建

### 重新部署眨眼就完成了，是不是没真正重建？

这是「源码与依赖都没有变化」时的正常结果，不是空转。重新部署会先比对三件事：

- 运行目录里源码树的哈希，与上次成功部署时记录的一致；
- `npm ci` 被跳过（lockfile 没变，`node_modules` 还在）；
- `.next/standalone` 产物仍然存在。

三者同时成立时，`next build` 不会重跑——它要解决的问题（源码变了 / 依赖变了）并没有发生。面板仍会重新装配 `public/` 与 `.next/static` 并重启应用，任务日志里会明确写出「跳过重新编译」。

只要改过源码，哈希就会变化，构建会正常执行。日志里每一步都带耗时（例如 `⏱ 构建前端 用时 1m12s`），可以直接看出时间花在哪里。

### 怎么强制重新编译？

1. 点「停止应用」——应用运行时的当前工作目录就是 `src/.next/standalone`，Windows 不允许删除活进程的工作目录；
2. 删除该项目的运行目录里的 `src/.next`；
3. 再点一次「重新部署」。产物不存在时，「跳过编译」的条件不成立，构建一定会执行。

路径默认是 `%LOCALAPPDATA%\AgileCampus\projects\<slug>\src\.next`（非 Windows 为 `~/.agilecampus/projects/<slug>/src/.next`）。

## PostgreSQL

### 换一台电脑部署时报 initdb 失败

先点击面板中的「检修数据库」。它会逐项检查部署环境，并给出可直接点击的修复项。常见原因：

- **退出码 0xC0000135 / 0xC000007B / 0xC0000142**：缺少 Microsoft Visual C++ 运行库（PostgreSQL 免安装包不自带）。安装 [VC++ 2015-2022 Redistributable (x64)](https://aka.ms/vs/17/release/vc_redist.x64.exe) 后重试，安装完不需要重启。
- **提示「以管理员身份运行」**：PostgreSQL 拒绝以管理员 / root 身份启动。请关闭面板，用普通用户双击启动，不要右键「以管理员身份运行」。
- **上一次 initdb 未完成，`pgdata` 中有文件但没有 `PG_VERSION`**：面板会自动把该目录原样改名为 `pgdata.broken-<时间>`（不删除，保留最近两份），然后重新初始化；检修中的「初始化数据簇并启动数据库（不删除现有文件）」也能完成同样的事。
- **路径问题**：运行目录包含非 ASCII 字符，或路径接近 260 字符上限时，使用 `--runtime-dir D:\ac-runtime` 换到更短的纯英文路径。
- **权限 / 杀毒软件**：把运行目录加入杀毒软件白名单，确认没有开启 Defender 的「受控文件夹访问」。
- **磁盘空间**：初始化数据簇与构建需要数百 MB，检修会显示运行目录所在磁盘的剩余空间。

启动数据库失败时，任务日志会附带运行目录 `logs/pg.log` 的末尾内容；原始错误比「60s 内没有起来」更有用。

### 目标电脑不能联网，或下载 PostgreSQL 失败

在任意能联网的电脑上下载：

```text
https://get.enterprisedb.com/postgresql/postgresql-16.13-1-windows-x64-binaries.zip
```

把 zip 原样放进项目运行目录的 `tmp/`（路径可在面板「设置」中看到，默认是 `%LOCALAPPDATA%\AgileCampus\projects\<slug>\tmp`），回到面板重新部署即可。

版本号可以换成其他 16.x / 17.x，但文件名必须保持 `postgresql-<版本>-windows-x64-binaries.zip` 的格式。

### 数据库可以重置吗？

可以，但不可撤销。面板提供「重置数据库」，会删库、重建、推送表结构并重启应用；执行前需要输入确认短语。若数据库来自外部连接而非面板托管的便携实例，请先确认没有其他人在使用。
